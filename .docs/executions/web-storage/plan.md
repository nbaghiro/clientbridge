# Web replica storage: OPFS on every browser

Status: planned and ready to execute on go. The decisions below were answered on 2026-10-27. Written 2026-10-27 on `web-storage`, based on `main` at `2d2cb40c`, and revised the same day after an independent review. No product code changes in this branch.

The web app keeps its PowerSync replica in two storage systems today: IndexedDB in Chromium and Firefox, and the origin private file system (OPFS) in WebKit regular windows, chosen from `navigator.vendor`. This plan moves every browser to one system, OPFS through wa-sqlite's `OPFSCoopSyncVFS`, chosen by a capability probe. A window that refuses OPFS (a private Safari window is the one we know of) keeps the replica in memory for that window (D1).

Most of the work also fixes today's WebKit path, which already runs on OPFS, so it ships before the switch. The switch itself is one small pull request behind one blocking gate: our own check for the Chrome on Windows OPFS crash (G2).

## 1. End state

- Chromium, Firefox and WebKit (desktop, iPadOS and iOS) open the replica with `WASQLiteVFS.OPFSCoopSyncVFS`. No code reads `navigator.vendor` or the user agent to choose storage.
- A window whose probe positively refuses OPFS opens the replica with `WASQLiteVFS.InMemoryVfs` (D1). A probe that doesn't answer, or fails for lack of space, never selects the fallback.
- `ReplicaStorage` in app-core is `"opfs" | "memory"`. The `EngineVendor` type, the vendor argument, the `indexeddb` arm and `IDBBatchAtomicVFS` are gone from the app.
- Sign-out deletes the account's three OPFS files (`<name>`, `<name>-journal`, `<name>-wal`), or lists them for deletion on the next start.
- Programmatic full-page navigations close the replica first, and a stuck open shows its own recovery message.
- The service worker precaches only the synchronous `wa-sqlite` build among the wasm files.
- `frontend/package.json` keeps its wa-sqlite override until a `@powersync/web` release pins 2.0.10 or later.

Out of scope: mobile storage, encryption at rest, `OPFSWriteAheadVFS` (opened only in Chromium in the bench; needs `readwrite-unsafe` handles), `AccessHandlePoolVFS` (one connection; failed the two-tab case), and PowerSync's opt-in `storageBucket` option (powersync-js PR 1142, open, Chromium-only API).

## 2. Where we start

`main` at `2d2cb40c`, checked 2026-10-27.

- `apps/web/src/lib/powersync.ts` maps `ReplicaStorage` to a VFS (`indexeddb` → `IDBBatchAtomicVFS`, `opfs` → `OPFSCoopSyncVFS`), resolves it once per page, opens the replica through `ReplicaController`, and calls `navigator.storage.persist()` on every connect.
- `replicaStorage(vendor, opfsSyncAccess)` in `packages/app-core/src/domain/sync.ts` returns `indexeddb` unless `navigator.vendor` is Apple's; on WebKit it returns `opfs` when the probe passes.
- `apps/web/src/lib/opfsProbe.ts` runs in a worker: it creates `.clientbridge-opfs-probe`, opens and closes a sync access handle, removes the file and posts `true`, or posts `false` on any error. There's no timeout, every probe uses the same name, and the page can't tell a refusal from a full disk.

## 5. Design

### 5.1 Storage selection and the probe

The probe stays in its worker, since `createSyncAccessHandle` exists only in workers, and changes in three ways:

- It uses a unique file name per run (`.clientbridge-opfs-probe-<random>`), so tabs probing at once don't collide.
- It posts `{ granted: true }` or `{ granted: false, error: <DOMException name> }`, so the page can tell a refusal from a full disk.
- The page waits 5 seconds for an answer and retries once with a new worker.

`replicaStorage(outcome)` in app-core decides, once per page, with no vendor argument:

| Probe outcome                                         | Storage                                                                                             |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| granted                                               | `opfs`                                                                                              |
| refused with `QuotaExceededError`                     | `opfs`; the open or the first write then reaches the existing `sync.problems.full` state            |
| refused with any other error, or a worker error event | `memory` (D1)                                                                                       |
| no answer after the retry                             | throws the `replica_stuck` error ([5.4](#54-locks-navigation-and-a-stuck-open)), never the fallback |

This matters because a regular window that landed on the fallback would hide the unsent edits in its OPFS file, and they'd be lost if the person then closed the window. The probe result isn't cached across loads, so a refusal can't stick to a window that would grant OPFS later.

### 5.2 The fallback (D1)

With memory, a refused window syncs into `InMemoryVfs` on each load. In WebKit, where PowerSync turns multi-tab off, each tab holds its own copy. The shell shows `sync.memoryNotice` for as long as the page runs, the hours page says `hours.savedInWindow` instead of `hours.savedLocally`, and while any outbox row is unsent the page registers a `beforeunload` handler.

What memory costs, stated plainly:

- Unsent working-hours edits are lost if the window reloads or closes before they upload. Desktop browsers show their own leave-page dialog; Safari on iPhone and iPad shows none, so there the notice and the hours wording are the only guard.
- Every load resyncs over the network (about 0.5 s of local work for 19k rows; the network part is measured in T1), and the window can't start offline. An offline start shows the existing first-sync error rather than an empty app.
- Tabs of one WebKit private window don't share data, and local preferences (recent searches, read marks) reset per load.

What IndexedDB would cost instead: a second VFS, the Asyncify build (2.3 MB) in the bundle and precache, a second set of storage tests, and WebKit's IndexedDB path for every private window, with the reload scatter and the CI stall above and the iOS jetsam bug for IndexedDB writes in workers. If the user keeps IndexedDB: the `indexeddb` arm and the `IDBBatchAtomicVFS` and `wa-sqlite-async` precache entries stay, T10 shrinks to the `XB-E2E-17` update, and the memory copy and prompt are dropped.

Chromium's incognito and Firefox's private windows follow the probe. Chromium's incognito grants OPFS, so it moves from IndexedDB to an in-memory OPFS that was slower in the bench (4.1 s against 1.5 s for the checkpoint) and that PowerSync reports has a lower size limit. Firefox's real private windows are unmeasured; the code doesn't change with the answer.

### 5.3 Multi-tab

`OPFSCoopSyncVFS` runs the database in a dedicated worker per tab; tabs take turns on the file's access handles through Web Locks and a `BroadcastChannel`. PowerSync turns `enableMultiTabs` on unless `SharedWorker` is missing, the user agent matches `Android|iPhone|iPod|iPad`, or `window.safari` exists. With it on, one `SharedWorker` syncs for every tab; with it off, each tab runs its own sync and one tab syncs at a time.

| Platform                      | Database                 | Sync                                   |
| ----------------------------- | ------------------------ | -------------------------------------- |
| Chrome, Edge, Firefox desktop | dedicated worker per tab | `SharedWorker`                         |
| Safari macOS                  | dedicated worker per tab | per tab                                |
| Safari and Chrome on iPhone   | dedicated worker per tab | per tab                                |
| Safari on iPadOS              | dedicated worker per tab | likely `SharedWorker` (desktop UA, Q2) |
| Chrome Android                | dedicated worker per tab | per tab                                |
| Memory fallback, WebKit       | dedicated worker per tab | per tab; tabs don't share data         |

We keep PowerSync's default. If T8 or T13 shows iPadOS resolves multi-tab on and fails the device checks, set `enableMultiTabs: false` when `navigator.maxTouchPoints > 1` and the UA says Macintosh, as one documented exception.

### 5.4 Locks, navigation and a stuck open

When a script navigates a WebKit page, the old page's database worker can keep its Web Locks (`ahp:/<name>`, which guards the file's access handles) until the browser quits (WebKit 316904), and the next page's open waits forever (powersync-js 808). A reload from the browser's own UI returns them. The mitigations, all in T5:

1. **`ReplicaController.close()`** (T3): stop uploads and history, disconnect, `db.close()`, keep the file. Closing releases the handles and the lock, and PowerSync then terminates the worker.
2. **`leave(url, how)`** in `apps/web/src/lib/powersync.ts`: when storage is `opfs`, await `replica.close()` (bounded at 2 seconds), then `location.assign` or `location.replace`. It replaces `Plans.tsx`'s local `leave()` and the `openUrl` callbacks in `Security.tsx` and `Login.tsx`. In memory mode it navigates without closing, so the leave-page prompt can still stop it. An eslint rule in `packages/config/eslint.mjs` rejects `location.assign`, `location.replace` and `location.reload` in `apps/web/src` outside `lib/powersync.ts` and `AdminLogin.tsx`.
3. **`pagehide`**: when storage is `opfs`, start `replica.close()`. It can't be awaited, so it narrows the race rather than closing it (the maintainer's point on PR 811). On `pageshow` with `persisted` set, the page came back from the back-forward cache with a closed replica, so `App` runs the session's full `restore()`. The focus handler only re-validates the session, which isn't enough.
4. **A stuck open.** `connectPowerSync` races `replica.activate` against 20 seconds and throws an error with `code: "replica_stuck"`. `useReplicaSession` maps it to a `"stuck"` failure, as it maps `offline_access_expired` today, and `App` shows `LoadFailed` with `sync.openStuckTitle` and `sync.openStuckBody`. The existing 30-second bound stays for the rest of the restore. Try again works when another tab held the file briefly; when WebKit kept a dead page's lock, only quitting the browser helps, which the message says.

### 5.5 Replica files: sign-out, retries and leftovers

- `ReplicaController` takes an optional `remove(filename)`; `discard()` calls it after `close()`. Mobile passes nothing.
- `packages/sync/src/files.ts` (web only) holds `removeReplicaFiles(name)`: it requests the Web Lock `ahp:/<name>` with `ifAvailable`, and only while holding it removes `<name>`, `<name>-journal` and `<name>-wal` from the OPFS root, ignoring `NotFoundError`. Holding that lock means no live connection holds the handles, so the outcome doesn't depend on how each engine's `removeEntry` treats an open handle. It returns whether the files are gone.
- The web `remove` adds the name to `cb_replica_trash` in `localStorage`, retries `removeReplicaFiles` every 500 ms for up to 5 seconds, and drops the name from the list once it succeeds.
- Before opening, `connectPowerSync` takes its own name off the list, tries once for every other listed name, and removes `.clientbridge-opfs-probe-*` leftovers. Taking its own name off first means a file listed by a failed sign-out, then reopened by the same account with new edits, is never deleted by a later start.
- Other tabs: when a restore finds no session (`App.tsx` lifecycle), it calls `replica.close()` instead of `pause()`, so the sign-out tab's retry usually succeeds within its 5 seconds.
- Files of accounts that never signed out are kept (D3). `.ahp-*` temporary directories are the VFS's own; it deletes unlocked ones when it starts.

### 5.6 When unsent edits can be lost

| When                                                | What happens to unsent working-hours edits                                                                                                                                                                   |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| First load of the switch in Chromium or Firefox     | Edits in the IndexedDB replica aren't read by the new build. With D2 as recommended they stay on disk and come back on a rollback. Testers open the app online with nothing pending before the deploy (T13). |
| A tab still on the old build during the deploy      | It keeps writing to IndexedDB until it reloads; nothing deletes that database under it.                                                                                                                      |
| Rollback                                            | Edits made after the switch stay in the OPFS file, unseen by the reverted build, and reappear on the next forward deploy (same file name). Stale ones come back as rejected for review.                      |
| Memory mode, window reloads or closes before upload | Lost (5.2).                                                                                                                                                                                                  |
| `leave()` in memory mode                            | Not closed first, so the leave-page prompt still guards.                                                                                                                                                     |
| Probe timeout or full disk in a regular window      | No fallback (5.1), so nothing is hidden.                                                                                                                                                                     |
| Sign-out                                            | Discarded after the existing warning (`sync.signOutBody`), as today.                                                                                                                                         |
| Trash retries at start                              | Never touch the account being opened (5.5).                                                                                                                                                                  |
| Safari's seven-day purge of an unused site          | Lost, as on today's WebKit OPFS path; an installed web app has its own counter (5.8).                                                                                                                        |

### 5.7 Service worker precache

Extract the plugin's asset list into `apps/web/scripts/precache.ts` and leave out the files the app can't load: `mc-wa-sqlite*` (the encryption builds; we pass no key), the `AccessHandlePoolVFS` and `OPFSWriteAheadVFS` chunks (T4), and with the switch `wa-sqlite-async*` and the `IDBBatchAtomicVFS` chunk (T9). The files are still served; they're only not precached, and the service worker passes requests for them to the network. In the earlier build this drops about 6 MB of the 7.1 MB of wasm.

### 5.8 `persist()`, quotas and eviction

- **`persist()`** (D4): call `navigator.storage.persisted()`; when it's false and `cb_persist_asked` isn't set, set it and call `persist()` once, after the first sync.
- **Quotas.** At 39.3 MB for 19k rows the replica fits every documented quota (Chromium and Safari 17 or later about 60% of disk per origin; Firefox at least 10% up to 10 GiB). T1 measures the largest core business's real file and flags anything over 60 MB. T3 checks that a quota error on OPFS reaches `sync.problems.full` (its matcher already covers `QuotaExceeded` and `SQLITE_FULL`).
- **Eviction.** Browsers evict an origin's storage whole and skip persisted origins. Safari also deletes script-writable storage after seven days of browser use without a visit, unless the site is an installed web app. Offline access already needs a server check within seven days, so what eviction adds is the loss of unsent edits; `architecture.md` states it, with no new code.

### 5.9 Copy

### 5.10 Web and mobile after the change

|             | Web                                                       | Mobile                                     |
| ----------- | --------------------------------------------------------- | ------------------------------------------ |
| Engine      | SQLite in wasm (wa-sqlite, synchronous build)             | native SQLite (op-sqlite)                  |
| Storage     | one OPFS file per account (plus journal and WAL entries)  | one sandbox file per account               |
| Concurrency | a dedicated worker per tab, sharing the file by Web Locks | one process                                |
| Fallback    | memory where OPFS is refused                              | none needed                                |
| Sign-out    | clear, close, delete the files                            | clear and close; the file stays, unchanged |

Both run PowerSync's core extension with the same `ReplicaController`, schema and outbox, so queries, transactions and the outbox behave alike. The remaining differences are storage limits (browser quota and eviction against device disk) and the tab model. Deleting the file on mobile sign-out would be a separate change.

## 9. Rollout and rollback

**Before production**

1. Every gate re-checked and recorded, G2 passed, and every web lane green twice in a row on the switch.
2. Staging testers open the app online with nothing pending, then the switch goes to staging.
3. Device checks on staging, each in a regular window and a private one, with the snippet's output in `progress.md`: Safari macOS (tab and installed web app), Safari iPadOS (tab and home-screen app, including an hour locked while offline), Safari iPhone, Chrome macOS, Chrome and Edge on Windows, Firefox macOS and Windows, Chrome Android. Each check signs in, waits for the first sync, reloads five times, opens a second tab, saves working hours offline, reloads offline (regular windows), reconnects, goes to Plans and back, signs out and confirms no `clientbridge-*` file is left. A private window also checks the banner, the hours wording and the leave-page prompt.
4. Two weeks on staging; testers report any stuck-open message or crash with the snippet's output, since the app has no client error reporting.

**Rollback.** There's no server or schema part. Revert the switch's pull request (T9 and T10) and deploy. Chromium and Firefox reopen their IndexedDB replicas as they were before the switch (D2 kept them), WebKit regular windows are unaffected, and WebKit private windows go back to IndexedDB. OPFS files made after the switch stay on disk and reappear on the next forward deploy. Waves 1 and 2 stay, since they help WebKit's existing OPFS path. There's no per-platform switch, by design.

## 10. Definition of done

- Every browser opens the replica on `OPFSCoopSyncVFS`, a refusing window on memory, and nothing else; no storage choice reads the vendor or user agent.
- Section 6's thresholds pass or each gap is accepted by the user in writing.
- Sign-out leaves no file of that account; a stuck open shows its recovery message; script navigations close the replica first.
- `make check` and every CI lane are green; `XB-E2E-17` to `-21` run in all three web lanes.
- The device checklist and the two-week soak are recorded.
- `architecture.md`, `engineering.md` and `decisions.md` describe what ships, and this folder is deleted.

## 11. Risks and open questions

- **R1. Chrome on Windows (G2).** Our runs may miss the crash, as the reporter's minimal page did; that's why it also gets a Windows device and the soak.
- **R2. WebKit's lost locks (G3, G5).** The mitigations cover script navigations and narrow the rest. The stuck-open message makes the remaining case visible, and quitting the browser recovers it.
- **R3. Memory mode** loses unsent edits on close, with no prompt on iOS.
- **R4. Chromium incognito** gets slower first syncs on in-memory OPFS and a lower size limit.
- **R5. Safari's seven-day purge** removes unsent edits after seven days without a visit, as today.
- **Q1. Firefox private windows and OPFS.** Unknown; the probe decides. Checked in T13.
- **Q2. iPadOS multi-tab.** Which `enableMultiTabs` PowerSync resolves with the desktop UA; read in T8 with the snippet, with the exception in 5.3 ready.
- **Q3. Does Linux WebKit reproduce 316904?** Recorded in T5.
- **Q4. The real replica size and first-sync time** of the largest core business. Measured in T1.
