Before you start

Environment, accounts & conventions

The whole suite runs against a seeded stack. On staging, swap hostnames/ports for the deployed URLs and use that environment's own Stripe/Twilio/Postmark test keys — the steps are identical.

1 · Bring everything up (localhost)

cd ~/Documents/code/clientbridge
make up          # Postgres :8702 · PowerSync :8704 · Redis :8703 · MinIO :8705 · stripe-mock :8708
make migrate     # apply the schema
make seed        # load "Birchbark Pet Studio" — the fixture every case starts from
make dev-api     # FastAPI on http://localhost:8701     (terminal 1)
make dev-web     # provider/admin app :8700             (terminal 2)
make dev-mobile  # Expo dev build (device/simulator)    (terminal 3, for mobile cases)
# Connect (customer) app on http://localhost:8709 — start it for public-link cases.

Surfaces & ports: API 8701 · Provider web 8700 · Provider mobile (Expo) 8707 · Connect/customer 8709.

2 · Seeded accounts — password demo1234

  • Owner — hannah@birchbarkpets.ca — everything (money, reports, team, settings).
  • Staff — diego@birchbarkpets.ca, priya@birchbarkpets.ca — limited role (for permission cases).
  • Business — "Birchbark Pet Studio", slug birchbark. Public booking: http://localhost:8709/book/birchbark.
  • Pending invite — sam.newhire@example.com.

The seed contains realistic data across every table (clients, pets, services/classes/products, packages, subscriptions, gift cards, bookings, invoices in all statuses, estimates, POS orders, payments, payouts, reviews, forms, contracts, threads). Re-run make seed to reset between runs (it truncates + re-inserts).

3 · API token (for curl-based checks)

API=http://localhost:8701
TOKEN=$(curl -s $API/auth/login -H 'content-type: application/json' \
  -d '{"email":"hannah@birchbarkpets.ca","password":"demo1234"}' | jq -r .access_token)
# owner:  -H "Authorization: Bearer $TOKEN"     (repeat with diego@… for a STAFF_TOKEN)

4 · Simulating external events

  • Stripe (payments, subs, refunds, payouts): forward test-mode webhooks with stripe listen --forward-to localhost:8701/webhooks/stripe, set the printed whsec_… as STRIPE_WEBHOOK_SECRET, restart the API. Pay with card 4242 4242 4242 4242. Advance subscriptions with a Stripe Test Clock.
  • Inbound SMS & Interac: POST to the webhook endpoints with the shared-secret header (see .env) to simulate an incoming text or a matched e-Transfer.
  • Notifications (email/SMS/push): in dev these use console/no-op providers unless real keys are set — check the API log to confirm a notification was built and "sent". With real test keys (Postmark/Twilio/Expo), check the inbox/phone/device.
  • Background jobs: the arq worker runs on cron; to test a job now, invoke its task directly (e.g. reminders, reap-unpaid, overdue sweep) or wait for its schedule.

5 · How to read each case

🟥 P0 — smoke / release-blocker 🟨 P1 — important ⬜ P2 — depth / edge WEB · MOB · CONNECT · API — platform

Mark each ✅ Pass / ❌ Fail / ⊘ Block; add notes. Progress + notes persist in this browser (localStorage); use Print / PDF to export a filled report. Filter to P0 for a fast smoke test before a release.

4-angle coverage. Every feature area is tested from four angles where they apply: the happy path, each error / 4xx, security & tenant isolation, and idempotency / edge. Sections 25–28 gather the cross-cutting angles that span the whole app.
